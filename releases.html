Index · Versions

Every release, on the record

Each BAS Hub release ships with structured patch notes (a plain-language summary and the full notes) bundled into the product itself, so they read offline. This page carries the same record. Version numbers are semantic for the suite: a new module class or breaking change moves the major, new features move the minor, fixes move the patch.

How versions are supported. The current release is 0.9.5, published as stable: it is the supported download, and the app’s update check reads the latest stable release, so it offers 0.9.5 to an installed 0.9.4, 0.9.3 or 0.9.2. 1.0.0 is reserved for the first release proven end-to-end in the field; the 0.9.x line is the pre-1.0 line. 0.9.3 was built and staged internally and superseded by 0.9.4 before publish: it was never a public release. Published releases stay downloadable permanently; a superseded published release remains available as a legacy build (unsupported, kept for reference and rollback), and when a newer release fixes a known defect in an older one, the older release’s entry says so plainly.

0.9.3

Legacy — unsupported Staged 2026-10-23, never published

BAS Hub 0.9.3: a new Home, a Library that files by site, and Reports+ complete at 59 subjects

Legacy build — unsupported. Kept for reference and rollback; the supported release is the latest.

Internal staged build, superseded before publish; never a public release. 0.9.3 was built, verified, and staged, and then superseded by 0.9.4 before it was ever published. Its GitHub release was created as a draft and stays a draft; there are no public downloads for 0.9.3, and nothing below should be read as a download offer. The notes below are kept as the record of what the staged build contained.

  • Home, rebuilt as a digest. Home is no longer a board of tiles. It opens on a single digest panel: the BAS Hub mark and version on the left, and on the right a readiness list that states, module by module, what is installed, what is ready, and what needs attention, in plain words. Your shortcut categories sit below it, unchanged in how they work.
  • My Files and Library: real folders, your site names, nothing saved for you. Filing is rebuilt around one rule: BAS Hub works in a session working set, and nothing is saved automatically. When you save, you save to My Files and Library, under a site name that is required, with a file name proposed for you that you can edit before anything is written. Folders for a site are built from that site name, and export categories appear under it as they are first used.
  • Reports+ is complete: 59 subjects, designed reports, not data dumps. Reports+ reaches its full catalog in this version: 59 subjects across vendor files, Network+, and Programmer+, each producing a designed report (a summary or detailed document with charts, tables, and per-subject options) in PDF, XLSX, CSV, or TXT. You pick sources, pick the subjects those sources can honestly support, set the options for each, preview, and file the finished report under its site.
  • Reports that compare, and a report for the whole site. A new family of Reports+ subjects works across sources instead of inside one file: mark sources as earlier and later, and Reports+ can build a source drift report, a program change report, a findings comparison, and a whole-site dossier that assembles what every selected source knows about one site into a single document.
  • Live reports: read the devices, then report on them. Reports+ can now report on live subjects as well as files: pick devices from the session, let BAS Hub enumerate their points over the connection you already have open, pick the roles and points the report needs, and build the report from what was actually read. Live configuration, live health, census, override, and trend subjects are all in this family.
  • Panel census fixed, archives opened selectively, backups reported. Three filing and panel jobs are finished in this version. A panel export (.P2) is now decoded by the one platform decoder, so Programmer+ and Reports+ count the same panel the same way: the thirteen held real exports now total 1,268 recognised modules where the module importer previously found 944, and panel point present values now flow through with the points. A Desigo ABT archive (.7z) can be imported selectively, group by group. And the backup family in Reports+ reports on the backups filed in the Library.
  • Reports under your control: licensing, redaction, and saved definitions. Reports+ adds the controls a report needs before it leaves the building: a licensing section that states the terms a report is issued under, a redaction control that removes what you mark before the file is written, and saved report definitions, so a report you build once (its sources pattern, subjects, and options) can be reopened and rerun as the same report.
  • Network health and commissioning, as reports. Two report families join the catalog. The network health report turns a Health run (yours, or one handed over from Network+) into a finished report with its verdict, findings, and evidence in report form. The commissioning family (VAV, AHU, and heat pump commissioning) reports a unit against its schedule and its tested modes, in the same designed form as every other Reports+ subject.
  • Programmer+: Programs in the tree, the Editor as the door, the Panel Inspector as a pane. Programmer+ is wired into the suite filing in this version. Programs filed under a site appear in the navigation tree under Programs, and opening one opens it in the Editor, with its origin stated on the Editor state line. Save to a site is an Editor door that files through the one save dialog. The Panel Inspector is now its own pane in the module, beside the Library, opening a panel file (.P2) in place and inspecting the decoded panel as tables.
  • Find, Health, Prove, and the Simulator: the everyday surfaces, finished. The Network+ surfaces you touch daily were finished to the same standard in this pass. Find is a grid: a sticky header and filter row above a scrolling body, a frozen selection and name block, bulk actions in a reserved bar that never moves the rows, and a filtered-empty state that names the active filters and offers to clear them. Health and Prove run behind one shared progress pattern, with run buttons that cannot be double-started. The Simulator run button keeps its geometry while a run is in progress.
  • Help, the guide, and the book say what the app now does. Every help surface was re-read against this version and rewritten where the app had moved: the filing model, the Find grid, panel import, Settings, and the Reports+ subjects (one explanation per subject) all describe the shipped behaviour. The User Guide chapters carry the same corrections, the in-app book is rebuilt from those chapters, and a wording fault in the guide read-me (the Failure logs group is inside Settings Diagnostics section) is fixed at its source, so the guide, the book, and Setup reading asset all carry the corrected line.
Known shortfalls, stated in the notes themselves: Live reads and writes are proven against simulated devices only. No live subject in this version has yet read a physical controller, and no bench or device write in this version is claimed as proven on real hardware. The display-scaling matrix (100, 125, 150, and 175 percent) for the redesigned surfaces is pending the owner Windows pass. The layout rules are pinned in the harness, but the four-scale visual proof on Windows is not yet done. Windows itself is the owner gate for this version: the packaged Windows build is verified by carving, hashing, and probing its payload on this machine, and is claimed as install-proven on Windows only after the owner installs and runs that exact package. The Windows ARM64 package is a candidate build only. It is held unpublished until an ARM64 Windows device has verified that it installs and runs. Source drift semantics are proven on held panel-export pairs. A drift proof on a same-station pair captured at two separated times is still awaiting an owner-provided sample, so drift on that exact case is not yet claimed. This version ships the one dark graphite product theme only. The eight vendor themes named in Programmer+ are editor code themes, not product themes. A light product theme remains a later release, with its own complete design pass. Proxy settings accept an address and a port only. A proxy that requires you to sign in is not supported.

The full notes for the staged 0.9.3 build are bundled in that build’s Help (Release notes). There is no public release page for 0.9.3: its GitHub release remains an unpublished draft.

0.9.2

Legacy — unsupported Released 2026-10-21

Legacy build — unsupported. Kept for reference and rollback; the supported release is the latest.

BAS Hub 0.9.2: one Settings, one Help, and every tool showing its work

Beta release, publicly downloadable. 0.9.2 was the current public release until 0.9.4 superseded it (0.9.3 was staged internally in between and never published), labelled beta: 1.0.0 is reserved for the first release proven end-to-end in the field. Downloads: Windows x64 (176,302,025 bytes, SHA-256 04c1ddc84f5fc88602b5406e921a267c79f727388e8eb27c1b154245a864c27d) and Linux x64 (177,130,062 bytes, SHA-256 716e6103a9b27d1e6eb21384d1d6a3e77f6226c227297a715dcf66bc1d980500), with the User Guide (PDF) and SBOM.json in the same release. Because this is a beta, the app’s update check (which reads the latest stable release) does not offer it: the beta is downloaded from this site. A Windows ARM64 package is in preparation: it is published after an ARM64 device has verified that it installs and runs.

  • One Settings, with a section rail. Settings is one window with a rail of sections down the side (General, each module's own settings, Updates, Data & backups, Diagnostics, and Failure logs) so everything you can adjust lives in one place and is found the same way every time. About is now its own dialog, separate from Settings, with a Copy version info button that puts the full version block on the clipboard for a bug report.
  • One Help for the whole suite. Help is one window for everything: the modules' help topics are composed centrally alongside the suite topics, so Network+ and Programmer+ help sits in the same index and the same search as the rest, and a module that isn't installed contributes nothing. Screens across the app carry help links that open Help at the topic for the screen you are on.
  • Help links now take you there. Links inside Help and the User Guide book now work as links: a cross-reference to another chapter jumps to that chapter, and a link to a website opens it in your browser. In the previous version those references were shown as plain text.
  • What's New, redesigned. The What's New popup is redesigned around the changes themselves: one headed item per change, each with its own short summary, its fuller detail on expansion, and its screenshot at the item it belongs to, never collected at the end.
  • The installer fits at every display scaling. Setup's action bar (the buttons you finish an install with) stays pinned and reachable at Windows display scalings from 100% to 175%, instead of being pushed out of reach at higher scalings. The install-reference text that sat in the wizard is gone from the wizard; Setup's /help carries it, where reference text belongs.
  • Find, rebuilt around scopes. Find in Network+ is rebuilt around scopes: the places a search can look. Each scope is a card that states plainly what that scope searches, only the scopes you choose actually run, and the results come back grouped by where they were found, with a count for each kind. If a scope you chose finds nothing, the result says so, a stated zero, not a silent gap. A per-run feed shows the search as it happens.
  • Test Bench as a walk. Test Bench is one walk in the order the work happens: discover, then the device, then its points, then write & control. There is one door into the bench, and a bench plan is a saved session you can reopen and rerun. If you arrive from a device that is offline, the bench opens scoped to that device and says why. Every write the bench makes goes through the safety engine: a backup is taken first, a receipt is kept, and backups are retained under the keep-count you set.
  • Health evidence you can read. Health presents its evidence as structure, not prose: the adapters it found and the findings it reached are each shown as a list you can scan. The MS/TP checks (the checks for a serial trunk) now run against that gathered evidence, and a Health run shows its progress and can be cancelled.
  • Watch finds the capture driver. Watch loads its capture driver (Npcap, the packet-capture driver) from where Npcap actually installs on Windows, not from where it was assumed to be. Setup and Network+ now run the same check for it, so the two cannot disagree about whether it is present. Under load, Watch's streaming now batches its work, so a busy capture stays responsive instead of falling behind.
  • Terminal: the host key is judged before the password. In the classic Terminal, an SSH connection now presents the server's host key (the fingerprint that identifies the machine you are connecting to) for your judgment before any password is asked for, the same order the rest of Network+ already used. You confirm the machine is the one you expect before you hand it a credential.
  • Programmer+ checks what the program does. Programmer+'s checks now reason about behaviour (what a program will actually do in the panel) not just how its lines are written. The check families cover: output tables that can never move their output (flat tables), timers that count the same time twice (double-counted timers), timers counting in the wrong direction, gates that can never open and gates that can never close, start-order dependencies between programs, what point names mean when read against a project point database, and values two programs both write with conflicting results. Five checks that previously could stay silent now fire when they should.
  • Programmer+: SOO import, Panel Inspector, and a fuller bench. Programmer+ gains its missing doors: import a sequence of operations (SOO) to start a program from the written sequence, open the Panel Inspector to see a panel as a panel, and drive the simulator with injected faults and saved scenarios (a sensor failed high, a command that never lands) so a program can be tested against the day going wrong, not just the day going right. The Library gains search and collections, and saving over an existing program now opens a save-collision dialog that shows you the collision and asks, instead of overwriting quietly.
  • Crash records only for real crashes. A host process ending without a name (a normal result of how some tools report back) is no longer recorded as a crash. Crash records are kept only for real process deaths, and the notices around them are written in plain language: what happened, and what, if anything, you need to do.
  • Home shortcuts, finished properly. Home's shortcuts gain a Browse button, so a shortcut's target is picked from the file dialog instead of typed from memory. A new shortcut takes the target program's own icon automatically, and its name arrives pre-filled from the target, yours to edit, not yours to invent from a blank box.
Known shortfalls, stated in the notes themselves: The capture-driver fix is proven on the test rig's code paths. Its first live confirmation is a Windows machine whose Npcap sits in its default install location; if Watch still lists no adapters on such a machine, its message now names the exact stage that failed, so the remaining cause can be found from that message. Panel import from a .P2 export: the first real panel export was decoded, but none of its points or programs were recognised. Rather than invent a panel, the importer declines that export: support for that export variant is not in this version. Proxy settings accept an address and a port only. A proxy that requires you to sign in is not supported. This version ships the graphite theme only. A light theme remains a later release, with its own design pass. The Windows ARM64 package is a candidate build. It will be published after an ARM64 device has verified that it installs and runs.

The full notes (each item’s detail and screenshots) are bundled inside the app (Help → Release notes) and on the 0.9.2 release page.

0.9.0

Internal first build: not a public release Built 2026-10-19

BAS Hub 0.9.0, Programmer+ and Network+ in one app, sharing one device inventory

Not publicly downloadable, by design. 0.9.0 is the internal first build, superseded by 0.9.1. Its notes below are the record of what the first build contained.

  • Programmer+ and Network+ live side by side on one home screen and share one device inventory, so a device you find in Network+ is the same record everywhere.
  • Programmer+ is rebuilt inside the Hub: a PPCL editor that checks as you type, block diagrams, decision tables, a simulator and debugger, the point database, and the code library.
  • Network+ starts from jobs in plain language: find what's on this network, look at a device, watch traffic, check the network's health, prove a loop works, talk to a device, and see what changed since last time.
  • BAS Copilot is an optional assistant that runs entirely on your computer. It is off unless you choose it during install, and it never sends your data anywhere.
  • If BAS Hub ever crashes, it saves a plain-language crash report on the computer and tells you about it on the next launch. Nothing is ever sent automatically.
  • Updates are yours to start: Settings has a Check for updates button. BAS Hub never checks, downloads, or installs anything on its own.

The full notes, as bundled with the product:

The Hub home

  • Your installed modules are tiles under Built-in Modules. Your own categories and shortcuts to other programs sit below them and can be rearranged by dragging.
  • BAS Copilot, when installed, is the icon at the top right. Settings is beside it, and the File / Modules / View / Help menu strip is at the top left.
  • There is no "active site" to pick. Sites appear only when you save or back something up, as a "Save to a site" option.

Programmer+

  • Editor with checks as you type and a findings panel that explains each finding, why it matters, the fix, and the manual page it comes from.
  • Block diagrams and decision tables that compile to PPCL, with plain-language refusals when something cannot compile.
  • Simulator and debugger: run a program against a plant, compare runs, scrub back through recorded passes, set breakpoints and watch points.
  • Point database, start/stop time optimization, vendor imports, and a code library that converts between text and blocks.
  • Programmer+ carries its own 21-topic help, available inside the module.

Network+

  • Find: discover what is on the network: BACnet, Modbus, and OPC UA devices land in the shared inventory.
  • Look: one page per device with its points and values.
  • Watch: capture traffic and read it back decoded in plain words, with capture completeness computed from the capture's own counters.
  • Health: the full diagnostics catalog with a three-part health score that always expands into the findings behind it, plus "Why is this device offline?" evidence runs.
  • Prove: a test bench for checkout plans and changes. Every write goes preview, backup, confirm, verify, and can be rolled back.
  • Talk: a real terminal for SSH, Telnet, and serial sessions, prefilled from the device record.
  • Records: what changed since last time, baselines with drift, and hashed exports that re-verify every file.

BAS Copilot

  • Optional at install. Setup checks your computer first and only offers model sizes it can run well; bigger sizes stay locked with the reason in plain language.
  • Runs entirely on your computer. No account, no cloud, nothing phones home; the one download is the model file at install, verified against its checksum.
  • It can explain and draft, never act: no device writes, no sends, no file changes come from the assistant.

Installing and changing modules

  • You choose the install location. Your data stays in the standard data folder wherever the program lives.
  • Run Setup again on an installed computer and it opens a maintenance screen instead: Update, Change modules, and Uninstall.
  • The Npcap packet-capture driver is offered inside the Network+ choice (Capture needs it) and installs from its own signed installer.
  • Uninstall removes exactly what the install record lists. Your data is kept unless you explicitly choose "also remove my data".

The release payload carries three modules (programmer-plus, network-plus, bas-copilot) and four Copilot model tiers. Installs are staged and committed as one move, so a failed install leaves the previous state untouched.

Reliability

  • Crash reports are structured files kept on the computer (the last 10, size-capped, with secrets kept out) and the next launch says in plain language that one was saved and offers to open the folder.
  • Multi-step operations are transactional in effect: nothing half-installs, and every device write is backed up before it happens.
