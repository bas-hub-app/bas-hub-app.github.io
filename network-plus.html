Find

Find sweeps the networks building-automation work runs on. Results land in one grid — sticky headers and a filter row, the tick and Name columns frozen, rows windowed so a big sweep stays scrollable — with a batch bar for acting on a selection. A scan states what it heard and what it did not; a device that stays silent is reported as silent, never filled in.

The device page

A device opens on its page: Properties, Points, Alarms, Trends, Schedules, and Records. Points is a live table — description-first labels, a column chooser, per-column filter and sort, values shown with their age, polling only while the page is open.

Trends covers stored device trends and live trending with points addable mid-trend; live series start when the point is added, and anything seeded from the device log is labelled with the seam visible. Trend definitions and schedules — the week, exceptions, calendars, the effective period — are viewed and edited through the guarded write door: a preview of current values first, and a read-back after the write. Fields a device does not let you write are locked, with the reason stated.

Test Bench

The Test Bench is where Network+ writes are planned and proven. A plan comes from a scan, from filed records, or is built by hand; write entries are marked [WRITE] and the preview reads current values before anything is sent. A backup is persisted before the first write, entries run in order with a per-entry log, and entries the plan marks for it are verified by read-back. Rollback runs through the same engine.

Practise mode runs the same plan against simulated peers, badged SIMULATED, with fault injection — so a plan can be rehearsed before it touches a live device.

Monitor Network Traffic

One capture, three views: Raw (packets beside the full bytes), Table (the same traffic translated into plain terms), and Combined. The translation never invents a field the bytes do not carry. Captures compare against each other and export to pcap.

Watch does not decrypt BACnet/SC traffic.

Health

Health runs 40 checks in layers and scores a device on three axes — Connected, Performing, Clean. No evidence, no score: a check that did not run shows “Not run”. “Why is this device offline?” runs the evidence chain and lists what it found, and a before/after compare shows what a fix actually changed.

Console

A VT terminal emulator in its own window — SSH, Telnet and serial, prefilled from the device record. A host key is judged before any password is asked; passwords live in session memory only. Whether a device offers a console at all is decided at the moment you connect, by the device’s own answer. Session logs are kept in memory for the session.

Records and backup

Records keeps revisit diffs and baselines, and a browser for filed records with SHA-256 fingerprints. A backup is a per-device configuration census — not a vendor program image. Restoring runs through a compare screen first: values that cannot be written back are named, never silently skipped.

Opening a backup stages it as a temporary network: browsable, every value badged as backup data with its taken-time, session-only, writing nothing.
