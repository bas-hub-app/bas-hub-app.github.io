04 · On stage

Each module, in turn

Scroll, and the stage changes hands: the home screen, the programming workbench, the network workbench, the reporting studio, and the optional assistant, each with the facts that define it. (With reduced motion set, the stage unpins and every module simply follows its text.)

The Hub

One launcher for the suite. The digest panel states, module by module, what is installed, what is ready, and what needs attention, in plain words; below it, your own categories hold shortcuts to the external tools you already use.

  • Ready states are earned, the digest says Ready only when the module checks out
  • No site mode: nothing to pick before your tools open
  • One settings home for the whole suite

Programmer+

The PPCL workbench: an editor that checks as you type, a block builder and decision tables that compile to program text, and a simulator and debugger for proving logic before a panel ever sees it.

  • 97 named diagnostics, every finding states the fix, the reason, and its source
  • 31 block types, sequences, and decision tables compile to PPCL
  • Time-scrub back through every recorded pass of a run

Network+

The network workbench, opened on jobs in plain language. One page per device is the spine; protocols are capabilities of the device, never separate rooms to visit.

  • 40-check health catalog, three axes, and an axis with no evidence says Not measured
  • Test Bench is the only door that writes, preview, backup, confirm, verify, rollback
  • Watch reads captures back in plain sentences, decode underneath

Reports+

The reporting studio. Vendor files and live subjects in; finished reports out — built, previewed, edited, and exported in one place, from one catalog the studio and its coverage page both read, so they cannot drift apart.

  • 60 report subjects, grouped by the job: inventory, programs, files, captures, network, commissioning, live, compare, site
  • File-fed and module-fed: files you add, and subjects handed over by Network+ and Programmer+ with Report on this…
  • Audiences, redaction, depth per build; configurations saved as named definitions; PDF, XLSX, CSV, TXT out

BAS Copilot (optional)

An assistant that runs entirely on your computer: chosen at install, sized to your hardware, and absent without a trace if you skip it. It explains and drafts; it never acts.

  • Zero egress by construction, the module ships with no networking code of its own
  • Four tiers, gated by RAM: Setup offers only what the machine runs well
  • Skip it, and there is no chat surface anywhere in the suite

06 · Trust, by design

Built like it has to earn its place on the laptop

◉

No telemetry. No phone-home.

Nothing is sent anywhere automatically, including crash reports. If BAS Hub ever crashes, it saves a structured report on your computer (the last 10 are kept, secrets kept out), and the next launch tells you in plain language that one was saved. Sending it anywhere is your act, never the app's.

⌂

Local-first data

One standard per-user folder; it survives updates and uninstalls; exports never contain credentials.

⬢

Secrets stay in the vault

Credentials are kept in Windows Credential Manager / DPAPI, never in plain-text files. Console passwords are held in session memory only and are never stored at all; console profiles by design have no password field.

◈

Write safety on live controllers

The Test Bench is the only door that writes. Preview from real reads → backup persisted first → your confirm → graded writes with read-back verify → a receipt, and rollback through the same path. A failed backup read stops the run cold: nothing is written. Browsing surfaces hold no write code path at all.

✓

Verified downloads

Release manifests are digitally signed and payloads are checksummed; a download that doesn't verify is refused, not installed. The installer itself verifies the payload hash before it stages a single file.

☰

Least privilege, nothing lurking

Per-user install, no administrator rights for the app, no background services installed, no listening sockets opened by default. Anything that listens runs only while you run it, shows its state, and stops when you stop it.

Honest surfaces. Where the app can't do something (a capture that proves less than it seems, a health axis with no evidence, a break a wire doesn't support) the surface says so, in words, on its face. That posture is a feature, and it is tested like one.
