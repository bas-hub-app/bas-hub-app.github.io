01 · Download & install

Four steps, no administrator rights

BAS Hub installs per-user, in a location you choose. Installs are staged and committed as one move: a failed or cancelled install leaves the previous state untouched, never a half-installed app.

Before anything installs, Setup runs this check on the real figures. This page is the quick answer: Setup is the authority.

  1. Get the file. Download the installer for your OS, Windows or Linux, each published separately. It is one self-contained file; Setup checks its own contents before installing anything.
  2. Run Setup. Double-click the installer (BAS-Hub-Setup-Windows-x64.exe on Windows). BAS Hub needs no administrator rights and installs for your user account only, in a location you choose.
  3. Pick your modules. The complete package, or just the modules you want. Two optional extras: BAS Copilot (Setup offers the model sizes this computer can run well, downloaded and checksum-verified) and Npcap (the packet-capture driver inside the Network+ choice: it runs its own signed installer, the one step that asks for administrator approval; everything else works without it).
  4. Launch BAS Hub from the Start menu or your desktop. Your data lives in %LOCALAPPDATA%\BAS Hub\data and is never removed by updates or by uninstalling.

The release also carries SBOM.json (the software bill of materials for the release) and the full User Guide as a PDF; the install reference that used to be a separate file now lives in Setup itself, on its Welcome screen and in its --help text. The Linux package installs the same way. Previous builds stay available on the releases page, notated as legacy, see Versions.

Install variants, silent deployment, module selection, exit codes (for IT)

The installer (BAS-Hub-Setup-Windows-x64.exe on Windows) is scriptable end to end. Every switch is optional; an interactive install and a silent one produce the same receipt.

SwitchMeaning
/silentInstall the complete package per-user, no UI
/modules=programmer-plus,network-plus,bas-copilotInstall only the listed modules
/ai=auto or /ai=<tier>Copilot model handling: auto picks the best tier this machine runs well; a tier name (helper, standard, solid, workshop) picks that tier; leaving Copilot out of /modules= skips AI entirely
/npcapInclude the Npcap driver step (its own signed installer; will prompt for elevation)
/target=<path>Override the install location
/update-checkReport whether an update is available; exit code 8 means yes
/verifyVerify an existing install against its receipt
/uninstallRemove the install (program files only; data kept). Add /purge to also remove user data

Exit codes: 0 ok · 1 error · 2 not installed · 3 bad arguments · 4 payload checksum mismatch · 5 downgrade refused · 6 cancelled · 7 verification failed · 8 update available (with /update-check).

Every install writes a receipt (install.json, inside the install folder) listing every file with its SHA-256, the modules chosen, and the Copilot tier, /verify re-checks a machine against it byte for byte.

02 · Updates

Updates happen when you say so

BAS Hub never checks for updates on its own: checking is a button you press when you're online. There are three routes to the same offer — Settings → Updates in the app, Setup's maintenance screen, or Setup's /apply-update command — and no one of them is the only path. Every download is verified by checksum and signature before anything is applied, and the previous version is kept until the new one has launched successfully once.

Update mechanics: how a release travels, step by step
  1. Check (only when you ask). The checker fetches the release manifest from the releases repository's latest release. Nothing is fetched in the background, ever; there is no schedule and no polling.
  2. Verify the manifest. The manifest is digitally signed (RSA) with the BAS Hub release key, whose public half is embedded in the app. A manifest that doesn't verify is refused outright.
  3. Plan. You see the new version, its notes, and exactly which modules would change, with sizes. Copilot items are separate and start unpicked.
  4. Download & verify again. Each file is checked against its SHA-256 from the signed manifest before anything is applied. A mismatch refuses the update.
  5. Apply, keeping the way back. The current version is set aside, not deleted. The new version must launch successfully once before the old one is let go; an update that fails to launch is reverted.
  6. IT control. An IT-policy switch can disable update checking entirely on managed machines, the Settings surface then says so, in words, instead of failing mysteriously.
Your data, maintenance, and uninstalling. Settings, logs and the activity log live in the suite's data folder, %LOCALAPPDATA%\BAS Hub\data. Device records do not live there: they live in the session working set while you work, and nothing is saved automatically — what you keep is what you file, into My Files & Library, the real folders on this computer, grouped by site under <site> / Exports /. Write-safety backups, captures and reports live where they are filed. Updates never touch any of it. Run Setup on a machine that already has BAS Hub and it opens as a maintenance screen instead: Update, Change modules, Verify, Uninstall. Uninstall removes exactly what the install receipt lists: the program, nothing else; your data is kept by default, and removing it too is an explicit choice, never the default. Exports never contain credentials.
